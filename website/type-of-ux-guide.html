Tap Menu. The drawer slides in, the page dims, and a tap outside closes it.

Key traits
  • Opens from a menu button
  • Dims the page behind it
  • Closes on outside tap or Esc
  • Holds secondary links
Best for

Apps with many sections, admin tools and sites with long menus.

Seen inGmail, Google Drive
How to design it
  1. Keep the top tasks outside the drawer.
  2. Put a clear Menu button in the top bar.
  3. Slide the drawer over the page and dim the rest.
  4. Close on scrim tap, Esc and after a link is chosen.
  5. Move focus into the drawer and return it when it closes.
Measure it
  • Drawer open rate
  • Time to find a hidden item
Quick testCheck that Esc closes it and focus goes back to the button.
Do
  • Group links with short headings
  • Show where the user is now
  • Trap focus while open
Don’t
  • Hide the main action only in the drawer
  • Open it on hover
  • Forget a visible close option
Code recipe
<button aria-expanded="false" aria-controls="dr">Menu</button>
<aside id="dr" hidden>...</aside>
btn.onclick=()=>{dr.hidden=false;btn.setAttribute("aria-expanded","true")}
addEventListener("keydown",e=>e.key==="Escape"&&close())

Seen inGoogle sign-up, GitHub
How to design it
  1. Validate on blur first, then on every key after an error.
  2. Write the fix, not the rule: "Add @ and a domain".
  3. Show an icon and text for error and success.
  4. Disable submit until all fields are valid, with a reason nearby.
  5. Mark required fields with text, not only a star.
Measure it
  • Form error rate
  • Time to complete
Quick testFill the form with wrong data and read each message aloud.
Do
  • Use aria-live for messages
  • Keep messages short
  • Show a strength hint for passwords
Don’t
  • Show errors before the user types
  • Use red alone as the signal
  • Clear the field after an error
Code recipe
<input id="e" aria-describedby="m">
<span id="m" role="status"></span>
e.oninput=()=>{const ok=/.+@.+\..+/.test(e.value);
  m.textContent=ok?"Looks good":"Add @ and a domain";go.disabled=!ok}

  • Undo restores the item

  2. Say what happened: "Deck deleted".

  4. Hide after 5 seconds and pause on hover.
  5. Announce it with role="status" for screen readers.
Measure it
  • Undo rate
  • Support tickets about lost data
Quick testDelete something and undo it with the keyboard only.
Do
  • Keep text under 6 words
  • Pause the timer on hover
  • Place it where the action happened
Don’t
  • Stack many toasts
  • Use a toast for errors that need action
  • Auto-hide without Undo for deletes

Key traits
  • Shapes match the final layout
  • Soft shimmer motion
  • Replaced by real content
  • No layout shift
Best for

Lists, cards, feeds and dashboards that load from a server.

Seen inFacebook, LinkedIn, YouTube
How to design it
  1. Draw the loaded layout first with the real sizes.
  2. Replace text and images with soft grey blocks.
  3. Add a slow shimmer, and turn it off for reduced motion.
  4. Swap in real content in the same place.
  5. Show an error state if loading fails after a few seconds.
Measure it
  • Perceived load time
  • Layout shift score
Quick testThrottle the network and watch for jumps.
Do
  • Match the real heights
  • Use 3 to 6 blocks, not 30
  • Respect prefers-reduced-motion
Don’t
  • Use a spinner on the full page
  • Animate fast and flashy
  • Show shapes that do not match
Code recipe

  background:linear-gradient(90deg,#eee 25%,#fff 50%,#eee 75%);
  background-size:200% 100%;animation:sh 1.2s infinite}

@media(prefers-reduced-motion:reduce){.sk{animation:none}}

Best for

Icon buttons, short definitions, hints and extra details.

Seen inFigma, Google Docs
How to design it
  1. Use a tooltip for a label or short hint, under 8 words.
  2. Show it on hover and on keyboard focus.
  3. Link it with aria-describedby.
  4. Use a popover for more text, with a button to open it.
  5. Close the popover on Esc and outside click.
Measure it
  • Help clicks
  • Support questions on the topic
Quick testTab through the page and check every tip shows.
Do
  • Place it so it never covers the control
  • Keep the same delay everywhere
  • Use plain words
Don’t
  • Hide key info only in tooltips
  • Use hover only
  • Put links inside a tooltip
